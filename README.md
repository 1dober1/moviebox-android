# Моя Кинотека — лабораторная работа №5.1

Простое Android-приложение по обязательным требованиям PDF.

## ТЗ

- Популярные фильмы: постер, название, год, рейтинг TMDB и кнопка избранного.
- Поиск по названию через API; отправка запроса кнопкой поиска на клавиатуре.
- Детали: постер, описание, жанры, длительность, дата выхода, страны и рейтинг.
- Избранное: добавление и удаление, просмотр без интернета, отображение заметок.
- Личные данные: заметка, отметка «Просмотрено», оценка 1–5 звёзд; сохранение кнопкой «Сохранить».
- Просмотренные: отдельная вкладка со всеми просмотренными фильмами, личными оценками и заметками, независимо от избранного.
- Нижняя навигация: популярное, поиск, избранное, просмотренные. Детали открываются нажатием на фильм.
- Пагинация популярных фильмов и поиска кнопкой «Загрузить ещё».
- Обработка загрузки, ошибок сети, неверного ключа и пустых результатов; повторная загрузка.
- Кэш страниц и деталей в Room. При ошибке API показывается сохранённая запрошенная страница.
- Постеры загружаются через Glide и сохраняются в дисковом кэше.
- MVVM, Repository, StateFlow, Retrofit, Room, RecyclerView с адаптером, ViewBinding и корутины.

Дополнительные анимации и тёмная тема не реализуются.
Офлайн доступны ранее загруженные данные и постеры, пока изображения остаются в дисковом кэше.
Избранное, заметки и оценки хранятся отдельно от данных API; обновление кэша их не изменяет.

## Неточности PDF

1. В функциональных требованиях разрешены Room/SQLite, но в технических требованиях и критериях указан Room.
   Используется Room.
2. Требование «минимум 2 endpoint'а» не покрывает все поля детального экрана.
   Используются три: `movie/popular`, `search/movie`, `movie/{id}`.
3. Примеры URL на странице 5 обрезаны при экспорте; отдельные строки `\` не являются частью запросов.
   Параметры запросов передаются через Retrofit, включая кодирование названия для поиска.
4. Заголовок дополнительных требований слился со строкой офлайн-кэширования.
   Пагинация и офлайн-кэширование относятся к обязательным пунктам.
5. Рейтинг TMDB и личная оценка — разные поля: первый отображается из API по шкале до 10,
   вторая сохраняется локально по шкале 1–5. Значение 0 означает отсутствие личной оценки.
6. В критериях достаточно трёх экранов, но в описании перечислены четыре функциональных экрана.
   Реализованы все четыре: популярное, поиск, избранное и детали.

## Запуск

1. Получить API Key (v3 auth) в [настройках TMDB](https://www.themoviedb.org/settings/api).
2. В `local.properties` добавить отдельной строкой, сохранив существующий `sdk.dir`:

   ```properties
   TMDB_API_KEY=ваш_ключ
   ```

3. Выполнить Gradle Sync и запустить приложение из Android Studio.
   После изменения ключа приложение нужно пересобрать. `local.properties` исключён из Git.

Проверка из терминала:

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

Для проверки офлайн-режима загрузить фильмы и их детали, сохранить фильм в избранное и заметку,
отключить интернет и перезапустить приложение. Проверить избранное, заметку и сохранённые детали.

Справка: [метод популярных фильмов](https://developer.themoviedb.org/reference/movie-popular-list),
[детали фильма](https://developer.themoviedb.org/reference/movie-details),
[URL изображений](https://developer.themoviedb.org/docs/image-basics).
